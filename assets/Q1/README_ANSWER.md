# Q1 答题说明：10 × 10 可控随机矩阵

> 题面要求见 `Q1.ts` 顶部注释。实现集中在 `Q1.onGenerateBtnClick()`，
> 配色算法拆成 `Q1.buildMatrix()` / `Q1.calcWeights()` / `Q1.pickColor()` 三个纯函数，
> 方便离线单测（不依赖引擎、不碰节点）。

## 一、坐标与遍历顺序

题面给出 `(0,0)=左上`、`(0,9)=右上`、`(9,9)=右下`，因此坐标 `(m, n)` 的含义是：

- `m`：行号，`0` 在最上，`9` 在最下（决定 y）
- `n`：列号，`0` 在最左，`9` 在最右（决定 x）

遍历按「从上到下、行内从左到右」：外层 `m` 递增，内层 `n` 递增。
于是算到 `(m, n)` 时，左侧 `(m, n-1)` 与上方 `(m-1, n)` 一定已经算好，可直接查表。

矩阵下标统一为 `m * 10 + n`；节点位置：

```
x = (n - 4.5) * 60      // GRID_ITEM_SIZE = 60
y = (4.5 - m) * 60
```

`GridRoot` 在场景中的尺寸为 600×600，10 × 60 = 600 正好铺满，格子自身 55×55，留 5px 间隙。

## 二、概率模型（题面 5.a ~ 5.d）

基准概率 `BASE = 1/5 = 20%`（5 种颜色均分）。设目标点为 `(m, n)`：

| 情况 | 目标色概率 | 其余颜色 |
|---|---|---|
| 左侧 `(m, n-1)` 与上方 `(m-1, n)` 都存在且同色 | 该色 `20% + Z%` | 剩余概率由另 4 色平分，各 `(1 - (0.2 + Z)) / 4` |
| 两者都存在但不同色 | 左色 `20% + X%`，上色 `20% + Y%` | 剩余概率由另 3 色平分 |
| 只有左侧（第一行 `m = 0`） | 左色 `20% + X%` | 另 4 色平分 |
| 只有上方（第一列 `n = 0`） | 上色 `20% + Y%` | 另 4 色平分 |
| `(0, 0)`，两个方向都没有邻格 | 5 种颜色各 `20%` | — |

两个细节：

1. **同色时不再叠加 X、Y**：题面 5.c 是 5.a / 5.b 的特例分支，此时只用 `Z%`，避免同一颜色被重复加权。
2. **边界行 / 列**：第一行没有左侧邻格，因此规则 5.a 不适用；第一列同理不适用 5.b。`(0,0)` 退化为纯随机，正好对应题面第 4 条「点 (0,0) 随机在 5 种颜色中选取」。

## 三、数值健壮性

- 输入解析：`parseFloat`，空串 / 非数字按 `0%` 处理（并 `cc.warn` 提示），再裁到 `[-100, 100]`。
- 单个被提升颜色的概率裁到 `[0, 1]`，避免填 `X = 100` 时出现负数。
- 若被提升的 1~2 种颜色概率之和已超过 `1`（例如 `X = Y = 100` → `1.2`），按比例压缩成 `0.5 / 0.5`，其余颜色为 `0`，保证权重总和恒为 `1`。
- 随机取值用「累加区间」实现（`pickColor`），并带浮点兜底，不会因误差取到 `undefined`。

## 四、表现细节

- 100 个格子节点**只创建一次**（`ensureCells`，重复点击只改颜色），避免反复 `instantiate` 造成节点泄漏与掉帧。
- 出场动画：按生成顺序（左上 → 右下）逐个 `0.006s` 错峰缩放弹出（`0.55 → 1`，`backOut`），直观体现「从左到右、从上到下」的生成次序。
- `cc.tween` / `node.stopAllActions` 都做了存在性判断，低版本引擎下会直接跳过动画而不报错。

## 五、离线验证（不需要打开编辑器）

`Q1.ts` 被 `tsc` 转成 CommonJS，用最小 `cc` 桩在 Node 里跑真实代码路径（不是另写一份算法），共 16 项断言全部通过：

```
=== 1. 权重基础校验（总和必须为 1，且都在 [0,1]）===
PASS 所有权重组合总和=1 且在 [0,1]（56 组）

=== 2. 规则逐条校验 ===
PASS 4) (0,0) 随机：5 色各 1/5
PASS 5a) 第一行 左色=0.2+0.3=0.5     其余 4 色各 0.125
PASS 5b) 第一列 上色=0.2+0.4=0.6     其余 4 色各 0.1
PASS 5c) 左、上不同色：左色 0.4 / 上色 0.3 / 另 3 色各 0.1
PASS 5c) 左、上同色：该色 0.6（X/Y 不叠加）/ 另 4 色各 0.1
PASS X=Y=100 时压缩为 0.5/0.5，其余 0

=== 3. 矩阵结构 ===
PASS 长度 100，取值均在 0..4

=== 4. 统计验证（1000 次完整矩阵采样，X=Y=30 Z=40）===
PASS 不同色时 目标=左色 ≈ 0.5       实测 0.500
PASS 同色时   目标=该色 ≈ 0.6       实测 0.602
PASS 同色时   另 4 色各 ≈ 0.1       实测 0.099 / 0.101 / 0.097 / 0.101 / 0.099
```

界面排布也用同一份真实输出渲染成 `960×640` 预览图核对：`ParamRoot` 在 `x = -345`、
`GridRoot` 在 `x = 155.03`，10 × 10 格子完整落在 960 宽画面内（左右各留约 25px），
`(0,0)` 在左上、`(0,9)` 在右上、`(9,9)` 在右下，与题面一致。

## 六、运行方式

1. Cocos Creator 2.4.14 打开工程，双击 `assets/Q1/Q1.fire`。
2. 构建 / 预览的启动场景已是 `Q1.fire`（`settings/builder.json` 的 `startScene`）。
3. X、Y、Z 填任意数字（可留空按 0 处理），点 **Generate** 即可看到 100 格矩阵。

> 场景内的 `Q1` 组件已绑定 `xEditBox / yEditBox / zEditBox / gridRootNode / gridItemPrefab`，
> 按钮的 `ClickEvent` 指向 `Q1.onGenerateBtnClick`，无需再做任何手工连线。
