# Q2：参考视频玩法还原

## 题目目标

仔细观察 `reference/example.mp4`，使用 Cocos Creator 2.4.14 和本题提供的碎图素材，还原视频中的玩法，制作可以由玩家实际操作的游戏。

视频是玩法、关卡布局、操作方式和表现节奏的主要参考。请自行分析视频中展示的规则与状态变化，并通过代码实现。

## 提供内容

| 内容 | 路径 | 说明 |
| --- | --- | --- |
| 参考视频 | `reference/example.mp4` | 原始参考视频 |
| 美术素材 | `texture/` | 共 77 张透明 PNG，已从三个图集拆出并还原旋转与原始尺寸 |
| 作答场景 | `Q2.fire` | 已挂载 Q2 脚本的起始场景 |
| 脚本入口 | `Q2.ts` | 请从此处开始，可自行拆分模块 |

图片包含场景与容器素材 10 张、拉针相关素材 36 张、金币序列帧 31 张。可自行整理用途；缺少的简单背景、文字或提示可使用引擎组件补充。

## 实现要求

1. **还原画面和关卡布局**：根据视频搭建主要场景，使用提供素材还原主要物体的外观、相对位置、层级和比例。
2. **实现真实交互**：视频中的关键操作应可通过鼠标点击或触摸完成。操作必须实际改变游戏状态，玩家可以自行决定操作时机和顺序。
3. **实现核心规则**：还原视频中关键操作触发的机关变化、物体运动、阻挡关系及后续结果，使操作与结果之间形成正确的因果关系。
4. **还原完整流程**：覆盖视频展示的主要玩法环节和状态变化，完成相应的结果判定与反馈，并提供重新开始当前关卡的方式。
5. **判断死局**：关卡进行中要根据当前物体位置、机关状态、阻挡关系和剩余可操作内容，判断是否已经无法达成目标。若剩余操作无论以何种时机和顺序执行，都无法再让目标达成，应判定为死局，并给出明确的失败反馈。死局必须由当前关卡状态得出，不能用固定步数、固定时间或预设失败脚本代替；局面仍有解时不得提前判定失败。判定为死局后，玩家可以重新开始当前关卡。
6. **还原主要表现**：尽量匹配视频中的关键动作、运动节奏和反馈效果。可使用物理系统或自行实现运动与碰撞逻辑，技术方案不限。
7. **保证可运行和可维护**：使用 Cocos Creator 2.4.14，保证场景正常运行、素材引用有效；合理拆分交互、关卡配置、运动逻辑及状态管理。

不得使用播放参考视频、预录动画或固定时间轴自动演示来代替玩法实现。操作后的结果必须由当前关卡状态和玩家输入驱动。

## 验收要点

- 打开 `Q2.fire` 后可进入作答实现的玩法，关键操作具有正确反馈。
- 对照参考视频，可辨认一致的主要布局、操作方式、核心规则和流程。
- 按视频中的操作方式可以复现对应结果；改变操作时机或顺序时，逻辑仍能根据当前状态正确响应。
- 局面仍有解时继续等待玩家操作；确认剩余操作已无法达成目标时，判定为死局并给出失败反馈。重新开始后，死局状态与物体、机关、关卡状态一并恢复到初始状态，无重复事件或残留对象。
- 浏览器预览中鼠标和触摸操作可用，常见屏幕比例下主要玩法区域可见、可操作。
- 项目无影响运行的报错，代码结构清楚，关键规则有必要说明。
