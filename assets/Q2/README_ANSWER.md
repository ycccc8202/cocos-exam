# Q2 作答说明 —— 拔针收集金币（Pull the Pin）

## 一、运行方式

1. 用 **Cocos Creator 2.4.14** 打开本项目（`cocos-exam`）。
2. 打开场景 `assets/Q2/Q2.fire`（容器、11 根针、罐子已经放好），点击预览。
3. 加载完成后进入玩法：**点击场景中任意针身即可拔出**（热区已放宽到 30px，不必精确点针头）。
4. **正解**：初始金币已**物理堆叠在碗内、被顶部水平横针 `hg-1` 托住（卡位）**。先拔 `hg-1` 放行，再**逐根拔左侧 5 根斜针**（`hg-7`~`hg-11`，截图红箭头所指、圆环在左上）让金币逐级下落；**右侧 5 根斜针 `hg-2`~`hg-6`（圆环在右上）一根都不能拔**——它们是把金币导向最左下开口的滑道兼槽位遮挡，任拔一根金币就会从对应槽位漏出、无法全部进罐，立即判定死局。成功只有一种：**上方金币最终全部沿容器最左下角出口掉进罐子**；其余任何局面都是死局失败（详见第三节「死局判定」）。针是真实的物理挡板——**针还插着金币就被托住，拔掉它金币立刻继续下落**。
5. 成功 / 死局后点击画面中的「重新开始」按钮可完整重开。

> 脚本入口：`assets/Q2/Q2.ts` 的 `start()`。**不创建、不修改场景中已有的任何主体节点**（`backgound` / `hg` / `bottle`），只读取它们的真实 position / angle / size：给已有针节点运行时挂物理碰撞体，新建不可见的静态碰撞墙；仅动态生成金币与文字 UI。

## 二、核心规则分析（来自参考视频）

视频是**拔针解谜**：上方沙漏容器装金币，中部交叉的蓝色针既阻挡金币又充当滑道，玩家拔针改变金币路径，使其落入左下罐中。参考视频金币特写显示：**金币真实地压在斜针上滑落、互相堆叠成金币山**，因此用物理引擎还原最贴近原效果。

从 `Q2.fire` 场景实测的针几何（圆环在顶部，X 交叉由节点 angle 形成）与视频对照：

| 针 | 场景角度 | 圆环端位置 | 形态 | 作用 |
| --- | --- | --- | --- | --- |
| `hg-1` | −86° | 右上 x≈+44 | 近水平横针 | **顶部闸门 / 卡位横针**：未拔时金币堆被它真实托在碗内，拔出后才放行；不判死局 |
| **右侧 5 根** `hg-2 ~ hg-6` | −36°~−38° | **右上 x∈[+58,+120]** | `/` 形（圆环右上，针尖左下） | **导流滑道 + 槽位唯一遮挡**：把金币导向最左下开口，并挡住各自槽位。**任一根被拔 → 死局，一根都不能动** |
| **左侧 5 根** `hg-7 ~ hg-11` | +42°~+44° | **左上 x∈[−59,−133]** | `\` 形（圆环左上，针尖右下） | **交叉阻挡针**：与 `/` 针形成 X 网格、暂时托住金币，**不遮挡槽位**。拔它们只放行金币，**不会死局**，是正解要逐根拔掉的针 |

> 左右由 `Q2.fire` 真实 `_trs.array` 解析出的圆环端（针头）x 坐标判定：右侧 `/` 针圆环端全部为正、左侧 `\` 针圆环端全部为负，与截图中「红色箭头所指的左斜列」和「右上斜列」完全对应。

- **金币的真实运动从初始阶段起就全部交给 Box2D 物理引擎**（2.4.x 内置 2D 物理）。金币创建即挂动态圆形刚体，针是静态矩形刚体：初始金币自由落体、彼此碰撞堆成金币山，被 `hg-1` 横针托住；拔针后落到斜针上被托住、沿斜面滑行、继续堆叠，行为由物理法则自然产生，不用预设路径、不用固定时间轴、不用脚本逐颗放流。
- **拔针即放行**：拔出针时立即把该针的 `PhysicsBoxCollider` 切成 `sensor` 并 `apply()` 写回 Box2D shape，压在其上的金币瞬间失去支撑，由重力自然继续下落 / 滑落 —— 这正是"拔针改变金币路径"的因果核心。用 `sensor` 而不是组件 `enabled` 切换，可避免某些引擎时序下"针已拔出但碰撞体仍在托住金币"。初始阶段的 `hg-1` 就是那根"卡位横针"：它的碰撞体实测横跨 x∈[−31.2, 43.8]，完全封住 y=13.6 处碗壁开口 x∈[−27.4, 36.4]，所以金币堆压在它上面不会提前漏进针阵。
- **金币不在颈口结拱**：轮廓是沙漏形，y=20 处净宽仅约 41px，48 枚颗粒同时挤过容易形成稳定拱桥。实现上用「薄墙 + 小半径（金币显示 18 / 物理直径 12，颈口可稳容 3 枚并排）+ 低摩擦 + 脚本夹回不清横向速度 + 颈口疏通」组合解决（详见第三节）；疏通严格限定在 y≥12，落到下方交叉针阵、被仍插着的针托住而静止的金币不受扰动，**保证"有插针遮挡就不能继续掉落"**。
- **容器碰撞体 = 轮廓封闭墙 + 5 个陷阱槽位 + 槽位下方绿色挡板**：按美术内腔边界逐段拼出内壁（上部碗壁 → 收窄颈口 → 笼子左右斜壁 → 左右壁），共 **33 段首尾重叠**（折线按美术重提后由 24 段增至 33 段，曲线拟合更细）；底部右高左低的斜底改为 **5 段可独立开关的槽位底墙**（`slotSegments()`）；**槽位正下方另有一道水平静态挡板**（截图里的亮绿色横线，`slotGuardSegment()`），合计 **39 段**。关闭时 5 段底墙与整条斜底完全等价。**金币始终被关在绿色圈线内**，唯一**成功**出口是**最左下开口**（x∈[−92,−68]、y≈−156，中心 −80.5 正对罐心）；斜底倾角 12.3° 把金币自然导向该开口。底部另有 **5 个槽位**（x∈[−68,97.7]，截图中红色箭头所指的竖直隔板格），各自只由**右侧 5 根 / 形导流针中的 1 根**遮挡（`SLOT_GUARD_PINS[i]` 对应第 i 个槽位）；该针被拔出即「没遮挡」→ 对应槽位底墙转 `sensor`，**金币允许真实滑落进槽位，但必须被槽位下方的绿色挡板挡住、停在绿色线之上，且滑落进去即判失败**（详见第四节）。左侧 5 根左斜交叉阻挡针（圆环在左上）与闸门针 `hg-1` 不遮挡槽位，拔它们只放行金币、不判失败。绿色挡板左端 x=−56 刻意避开成功开口落点，绝不挡住进罐金币。
- **入罐 / 槽位失败 / 流失**：金币落到罐口高度 (y≤−210) 且横向在罐口范围 (|x+80.5|≤42) 判定入罐；**金币穿过已开放槽位的底墙、落到 y<`SLOT_FAIL_Y`(−158) 即判 `slot` 失败**（提示「金币滑落进底部槽位」，游戏立即结束），金币随即被**固定在绿色挡板顶面 y≈−160 并保留显示**，不再向下淡出、绝不出现在绿线下方；落到容器底部以下却不在开口/罐口方向、掉出画面底部或横向穿出封闭轮廓，判 `miss` 流失并立即淡出，同样无法全部收集 → 死局。
- **堆叠与翻转分离**：金币刚体 `fixedRotation=true`（物理上不自转，避免堆叠发疯），绕 Y 轴的旋转观感仍由 31 帧序列帧表现；**已结算入罐的金币停止翻转**，罐内是一堆静止的金币，不再持续闪动变形。碗内 / 下落中的金币全程统一尺寸（不再"掉落前缩小、掉落时放大"）。
- 罐口参数由 `Q2.fire` 中 `bottle`（scale 0.7，位置 −81.2,−256.7）与 `bottle2` 实时变换等比换算；针几何全部由节点真实 position / angle / size 推导，改场景后自动适配。
- 目标为全部 **48 枚**金币进罐；拔针**不可逆**。

**玩法要点**：本质是"识别哪些针能拔、哪些不能拔"的物理谜题——**可安全拔的是顶部闸门针 `hg-1` 与左侧 5 根左斜交叉阻挡针 `hg-7`~`hg-11`**：先拔 `hg-1` 放行，再逐根拔左侧 5 根让金币逐级下落，沿保留的右侧 / 形导流滑道、经右高左低的斜底汇入**最左下开口**进罐。金币不会跑到圈线外；**底部 5 个槽位各只由右侧 1 根 / 形导流针 `hg-2`~`hg-6` 遮挡**，任一根右侧针被拔（拔针不可逆）→ 对应槽位永久失去遮挡，此后金币下落必有一部分从槽位漏出、被绿色挡板接住停在绿线之上，**无法全部进罐 → 立即判定死局**。所以**右侧 5 根一根都不能动，误拔任意一根即失败；左侧 5 根与 `hg-1` 任意组合拔取都不会死局**（这正是正解）；重开可完整复原。

### 物理引擎关键实现

- **启用**：`cc.director.getPhysicsManager().enabled = true`，重力 `cc.v2(0, -900)`（比默认 −320 大，下落节奏贴近视频），提高 solver 迭代到 10 保证 48 枚堆叠稳定。
- **针碰撞体**：每根已有针节点运行时挂 `RigidBody(Static)` + `PhysicsBoxCollider`（尺寸按针身收窄）；针节点自带 angle，碰撞体跟随旋转形成斜面。摩擦 0.10，保证金币能沿针滑落。
- **金币刚体**：`Q2Coin.reset()` 里即挂 `RigidBody(Dynamic)` + `PhysicsCircleCollider`（半径 **6**、显示直径 **18**、密度 1.2、摩擦 0.03、`bullet=true` 防穿透细针、`fixedRotation=true`），零初速自由落体。
- **初始物理堆叠**：金币一创建就在碗内挂零初速动态刚体，受重力落到 `hg-1` 上堆成金币山；`wait` 阶段仍每帧做轮廓约束与序列帧翻转，但不做入罐 / 流失结算。`Q2Game` 在 `ready` 状态也推进金币，所以初始画面就是真实物理堆叠，而不是静态点阵。拔 `hg-1` 时一次性 `release()` 切到结算阶段并给一点向下初速度，运动完全由针碰撞体转 `sensor` 触发，不再有脚本 `gather` / 逐颗放流。
- **轮廓壁 + 5 段槽位底墙 + 绿色挡板**：把 `backgound_0/2/1` 按场景坐标合成后取「深红内腔」左右边界（按美术像素直取，取代原先照手绘绿线拟合的做法），逐高度整理成两条内壁折线 `CHAMBER_LEFT / CHAMBER_RIGHT`（左 18 点、右 17 点）；`wallSegments()` 返回 **34 段**（左 17 + 右 16 + 整条斜底 1），`buildWalls()` **取前 33 段轮廓壁**，斜底改用 `slotSegments()` 的 **5 段可开关槽位底墙**（沿 x∈[−68,97.7] 均分、段长 33.9px、各加墙厚 8 首尾重叠，关闭时与整条斜底完全等价）；再用 `slotGuardSegment()` 在**槽位正下方建 1 道水平静态挡板**（x∈[−56,97.7]、y=−170、厚 8），共 **39 段**。**左壁末端与最左槽位底墙左端之间刻意不连墙** → 形成唯一成功开口 x∈[−92,−68]；绿色挡板左端 −56 也刻意避开该开口的落点（实测落点右缘最大 −62.3，余量约 6px），因此不挡进罐金币。
- **槽位放行（没遮挡）与绿色挡板接住**：每个槽位**只由右侧 1 根 / 形导流针**遮挡（`SLOT_GUARD_PINS[i]` = `hg-2`~`hg-6` 依次对应 slot 0~4，针尖 x≈−66/−33/1/32/64 恰好落在各槽中心）；**左侧 5 根 \ 形交叉阻挡针 `hg-7`~`hg-11` 与闸门针 `hg-1` 不遮挡任何槽位**。`Q2Game._syncSlots()` 在每次拔针后只检查 `SLOT_GUARD_PINS[i]`：**该针被拔出**即视为「没遮挡」，`Q2Physics.setSlotOpen(i,true)` 把该段底墙转 `sensor` + `apply()`，金币可真实穿过斜底滑落进槽位；`clampCoin()` 对开放槽位区域的金币**跳过夹回**，让它顺利落下（不再被钉在斜壁上）。**槽位下方的绿色水平挡板是常驻实体、不参与槽位开关**，从物理上拦住金币，使其停在绿色线之上、不再继续滑落到画面下方 / 罐子方向。重开时 `resetSlots()` 全部恢复为实体。
- **碗内投放点贴合轮廓且互不重叠**：从 y=40 起、层距 16，每层可用宽度取 `chamberLimits(y)` 的真实内壁，按 ≥ 金币物理直径的间距（15px）均匀铺开，从下往上填满 `COIN_TOTAL` 即止。6 层 2/5/8/10/12/11 共 48 点，全部落在墙内、同层最小中心距 14.34px ≥ 直径 12px，挂刚体瞬间零重叠，不会被 Box2D 强力弹飞、也不会在颈口预挤出致密死堆。
- **脚本越界兜底（不清切向速度）**：`chamberLimits(y)` 按高度插值出该处允许的 x 范围（右壁以下改由斜底表面给出右边界）；`Q2Physics.clampCoin()` 只在金币**明显穿出内壁超过 `CLAMP_TOLERANCE=3`** 时才夹回、`syncPosition(false)` 写回刚体，且**只清掉仍冲向墙外那一侧的横向速度，保留沿壁下滑的切向速度**。旧实现每帧把贴壁金币夹回并把 `vx` 无条件置 0，等于把金币钉死在漏斗斜壁上，是"拔针后整堆金币不下滑"的直接原因。金币离开容器后不再夹回，交由结算判定。
- **颈口疏通（anti-jamming）**：物理阶段对「y∈[`UNSTICK_MIN_Y=12`, 150] 且已静止 `UNSTICK_TIME=0.30s`」的金币施加一次轻微横向错动 + 向下速度（`UNSTICK_VX=70` / `UNSTICK_VY=−90`），打散窄颈口处的颗粒拱桥；各枚初始相位按序号错开，避免整堆同步抖动。范围严格限定在 y≥12 —— 落到下方交叉针阵、被仍插着的针托住而静止的金币不参与，规则不被破坏。
- **结算**：脚本每帧只读金币节点坐标，落入罐口判 `jar`；**在轮廓夹回之前、用 Box2D 真实坐标判定 `slot`** —— 金币 y<`SLOT_FAIL_Y`(−158) 且落在已开放槽位即判失败（提示「金币滑落进底部槽位」，主控立即结束游戏）。判 `slot` 时进入 `trapped` 阶段：**不移除刚体、不做任何传送**，金币继续按物理掉进槽位格子、被格子侧壁与槽底兜住后自然停住（见第四节最新一轮"槽位=物理口袋"）。落到容器底部以下却不在开口/罐口方向、掉出画面或横向穿出封闭轮廓判 `miss` 并淡出。入罐金币 tween 到罐内散落格位保留显示。

### 死局判定（由当前关卡状态确定性得出）

题目明确要求死局必须由当前关卡状态 / 机关状态 / 阻挡关系推导，不能用固定脚本 / 步数 / 时间代替，且**有解时不得提前失败**。

**胜负定义（用户规则）**：成功 = 上方金币最终**全部沿容器最左下角出口**掉落到罐子里；其余任何「无法全部进罐」的局面都算死局失败。

**针的左右分组（由 `Q2.fire` 真实 `_trs.array` 几何确定）**：解析 quaternion 还原 2D angle，再按局部 +Y 方向算圆环端 x —— 右侧 / 形导流针圆环端 x 为正、左侧 \ 形交叉阻挡针圆环端 x 为负。**每个槽位只由右侧 1 根 / 形导流针遮挡**，左侧 5 根与 `hg-1` 不参与槽位开关。

**判定依据 = 真实物理结果 + 机关状态 + 通用无解兜底**（三层，都不依赖步数 / 时间脚本）：

- 5 个底部槽位各由**右侧 1 根 / 形导流针**（`SLOT_GUARD_PINS`：`hg-2`→slot0、`hg-3`→slot1、`hg-4`→slot2、`hg-5`→slot3、`hg-6`→slot4）遮挡。拔针不可逆 → 对应槽位底墙转 `sensor` 开放，该处金币可真实漏下去。
- **① 真实漏币（主判据）**：金币穿过开放槽位的斜底、落到 `SLOT_FAIL_Y(−158)` 以下 → `Q2Coin` 报 `slot` → `Q2Game.update()` 立即 `_lose('金币滑落进底部槽位')`。这是「局面已无解」最硬的证据，**不预设任何脚本**。
  - 实测（Box2D 仿真，闸门已拔、拔掉该针后再拔左 5 根）：拔 `hg-2` → **26 枚真的落入 slot0**；拔 `hg-3`~`hg-6` → **0 枚落入，48/48 仍全部进罐**（金币落点集中汇聚在 slot0 上方，slot1~4 即使开放也没有金币经过）。
  - 正因为如此，**不能**用「拔任意右侧针即判负」的纯规则：拔 `hg-6` 时局面仍可全收集，判负就是题目禁止的「有解却提前失败」。
- **② 规则判定（可开关）**：`GEO.FATAL_ON_GUARD_PULL`（**默认 `false`**）—— 置 `true` 时 `_evaluate()` 会在 `hasOpenSlot()` 为真时立刻 `_lose('右侧遮挡针已拔，金币会从底部槽位漏走')`，即用户最初「拔右针即死」的严格口径；默认关闭则完全交给 ①。
- **③ 通用「无解」兜底**：11 根针全部拔完（再无任何操作可做）、金币全部静止（`STALL_VSQ=400`，<20px/s）、持续 `STALL_TIME=1.2s` 仍未全进罐 → `_lose('金币卡在中途，已无解')`。兜住几何异常 / 卡死等任何未预料的僵局。
- 由此得到的实际规则：
  - 未拔针 / **只拔闸门针 `hg-1`** / **只拔左侧 5 根 `hg-7`~`hg-11` 任意根或全部** / `hg-1`+左侧组合 → 槽位仍有遮挡（`hasOpenSlot()` 为假）且金币不会漏 → **仍有解，绝不提前判负**；
  - 拔右侧 `hg-2` → 金币真漏进 slot0 → **判负**（真陷阱）；
  - 拔右侧 `hg-3`~`hg-6` → 不提前判负；局面若仍能全收集就继续玩，真漏了才失败。
- 判负时 `_lose()` 会调用 `Q2Coin.freeze()` 把尚未结算的金币移出物理世界并停帧，剩余金币不再继续下落 / 掉出屏幕；`Q2Physics.resetSlots()` 在重开时把槽位状态复位，重开后回到「有解」。
- 已删除旧的 `Q2Coin.canReachJar` / `_simulate` / `_physicsStep` 线段推演、静止复检 `consumeJustRested()`、8 秒固定时间 `_stallTimer` 兜底（注意与新的 ③ 不同：③ 只在「针已全部拔完、金币真的静止」时才计时，是无操作可用后的兜底，不是用来替代判定）。

物理引擎负责"看起来真实"，槽位遮挡状态负责"判定有解无解"，两者共用同一份 `_slotOpen`，既还原视频掉落效果，又满足死局判定要求。

**逐根验证**（按 `SLOT_GUARD_PINS` 复刻 `_syncSlots()` + `hasOpenSlot()` + `_evaluate()`）：未拔针 / 单拔 `hg-1` / 单拔左侧 `hg-7`~`hg-11` / 全拔左侧 5 根 / `hg-1`+左侧全部组合 → **0 开放、均不判负**；单拔右侧 `hg-2`~`hg-6` **5/5 全部判死局**，`hg-1`+右 1 根 / 左 2 根+右 1 根 / 全拔右 5 根 / 全拔 11 根等含右针组合也判死局；重开复位后 0 开放恢复"有解"。分组完整性：遮挡针 5 根、放行针 5 根、无重复 / 缺漏 / 野针，与 `Q2.fire` 真实 angle 与圆环端 x 正负完全吻合（结论 PASS）。

### 本轮修正：金币没有下滑（用户反馈「如图，金币没有下滑」）

- **现象定位**：放大截图可见，`hg-1` 横针已不在画面中（已拔出），金币最低一排**正好卡死在收窄的颈口**，颈口以下的笼子 / 交叉针阵里一枚金币都没有，罐子也是空的 —— 即"拔了针、金币却整堆不动"。多颗粒仿真复现：48 枚全停在 y≈29.6，0 枚进入下方。
- **根因**：
  1. 轮廓是沙漏形，**y=20 处最窄**：内壁仅 49.1px，扣掉墙厚后净宽约 37~41px，只容 2 枚金币（直径 16）并排；48 枚颗粒同时挤过必然结出稳定**拱桥（jamming）**，尤其 `fixedRotation=true` + 摩擦。
  2. **脚本 `clampCoin()` 每帧把贴壁金币夹回并把 `vx` 无条件清 0**：在漏斗斜壁上，金币需要横向速度才能沿壁向颈口汇聚，横向速度被反复清零等于把金币"钉死"在斜壁上，拱桥永远无法自行松动。
  3. 投放点旧算法用 `bowlHalfWidth()`（碗形半宽 40~108）决定每层枚数，却把 x 铺在 `chamberLimits()`（颈口附近仅 32px）里，**底层 4 枚间距只有 8px < 金币直径 16**，挂刚体瞬间严重重叠，被 Box2D 强力弹开后预挤出一片致密死堆。
  4. 摩擦偏大（金币 0.12 / 墙 0.08）、墙厚 12（向轮廓内侵入 6px）进一步收窄通道。
- **修复**（`Q2Config.ts` / `Q2Physics.ts` / `Q2Coin.ts`）：
  - **clamp 不再清速度**：只在越界超过 `CLAMP_TOLERANCE=3` 时才夹回，且只清掉"仍冲向墙外"那一侧的横向速度，保留沿壁下滑的切向速度。

### 本轮修正：金币只在「真实下落」时翻转，静止时定格（2026-11-21，用户「金币静止状态下不进行持续的转动，只有下落过程中才转动」）

**原实现**：`Q2Coin.update()` 里序列帧翻转是按**固定时间轴**推进（`SPIN_FPS=18` 帧/秒，与速度无关）。结果碗内被 hg-1 托住的金币山、槽位里停住的金币、甚至整堆静置的初始化阶段，画面一直在匀速翻面——观感上像一堆"永不停转"的薄片在闪，也容易被误读成"金币数量在变"。

**现实现**（与物理一致，改为「路程驱动」）：

- 每帧从刚体取速度 `speed = |linearVelocity|`，累计滚动路程 `_spinDist += speed * dt`；
- 每累计满 **`SPIN_DIST_PER_FRAME = 10px`** 翻一帧（31 帧循环）：**下落越快翻得越快，慢速滑动慢慢翻，静止完全不翻**；
- 速度 **`< SPIN_MIN_SPEED = 20px/s`** 时直接把进度清零，视为静止——这个阈值与判「卡死」的 `STALL_VSQ`（400 ⇒ 20px/s）同口径，保证"引擎认为静止"与"画面静止"一致；
- 单帧最多连翻 4 帧（极端速度下丢帧），避免高速下落时闪烁；
- `done`（罐内 / 流失）金币本就不翻；现在 `wait`（碗内堆）、`trapped`（槽位里停住）也一并定格。

|---|---|---|
| 初始化 / 碗内被横针托住的金币山 | ≈0 | **完全定格**（不再持续转动） |
| 颈口流动、沿针滑落 | 50~200px/s | 5~20 帧/秒，越快越快 |
| 槽位里停住（死局画面） | ≈0 | **定格** |

### 本轮修正：拔 hg-2 先「预判」再判负 —— 金币还能全进罐就不算失败（2026-11-21，用户「预判一下假如金币都能掉落罐子里，这时候拔出 hg-2 也不能判断失败」）

原规则是「拔 hg-2 当帧无条件判死局」，但它忽略了一种情况：**金币已经全部流到左下出口列、马上落进罐子**时才去拔 hg-2，此时 slot0 的洞敞开也漏不到任何一枚，局面其实仍可解 —— 不该判负。

**实现**：新增 `GEO.FATAL_PIN_PREJUDGE = true` 与 `Q2Game._fatalPinDoomed()`，`_evaluate()` 命中 `FATAL_PINS` 时先做几何预判，再决定是否 `_lose()`：

```
仍在未结算状态（还没入罐）的金币中，只要有一枚中心 x > -68（出口右缘 = 最左槽左边界）
  → 它接下来必须从右侧横穿槽位区才能到左下出口，slot0 已敞开 → 必漏 → 判负；
所有未结算金币的中心都已 ≤ -68（全部进了出口列）
  → 它们被出口两侧壁夹住，只会垂直落进罐口 → 不判负，关卡继续跑完全程。
```

预判是**纯几何、零开销**（只遍历一次金币的当前 x），不跑模拟、不影响帧率；`done`（已进罐/已流失）金币不参与。

**离线验证（现行轮廓、闸门 + 左侧 5 针已拔，在 11 个不同时刻拔 hg-2，对比「预判」与「物理最终结果」）**：

| 拔 hg-2 时刻 | 未结算金币 | 其中 x > −68 | 预判 | 最终 | 一致 |
|---|---|---|---|---|---|
| 2.7s | 48 | 27 | 无解 | 41 进罐 + **7 漏槽**（判负） | ✔ |
| 3.0s | 48 | 20 | 无解 | 40 + **6** | ✔ |
| 3.5s | 39 | 14 | 无解 | 42 + **6** | ✔ |
| 4.5s | 22 | 5 | 无解 | 43 + **4** | ✔ |
| 6.0s | 1 | **0** | **有解（不判负）** | **48 + 0 全进罐** | ✔ |
| 8 / 10 / 12 / 14 / 16 / 20s | 0 | 0 | 有解 | 48 + 0 | ✔ |

**11/11 全部吻合**：预判说「有解」的时刻，物理上确实 48/48 全进罐（一枚不漏）；预判说「无解」的时刻，物理上一定有金币漏进槽位。所以这条预判既不会误判失败（金币能全收时拔 hg-2 不再弹死局），也不会漏判（真会漏的时候照样当帧判负）。

**行为**：拔 hg-2 → 预判有解 → 不判负、正常跑完 48/48 进罐 → `_win()`；预判无解 → 当帧判负（输入立刻锁）→ 0.6s 金币落定冻结 → 1.0s 弹结算面板。

- 代码改动：`Q2Config.ts`（新增 `FATAL_PIN_PREJUDGE = true`）、`Q2Game.ts`（`_evaluate()` 加预判分支 + 新增 `_fatalPinDoomed()`、更新注释）；`tsc --noEmit` 0 error。
- 想退回「拔 hg-2 无条件判死」的旧口径，把 `FATAL_PIN_PREJUDGE` 置 `false` 即可；想调整"危险线"，改 `_fatalPinDoomed()` 里的 `GEO.CHAMBER_GAP_RIGHT`。

### 本轮修正：「金币真的落进槽格」优先级最高（2026-11-21，用户要求）

判负理由现在有严格优先级，**物理上真有金币漏进槽格 > 一切规则判负**：

| 优先级 | 判负来源 | 面板文案 |
|---|---|---|
| **1（最高）** | **金币真的穿过敞开槽底落进槽格**（`Q2Coin` 报 `slot`） | **失败 / 金币已落入槽内** |
| 2 | 拔 `FATAL_PINS`（hg-2）且预判无解 | 死 局 / 金币最终会落入底部槽位 |
| 3 | 金币掉出罐外（`miss`） | 死 局 / 金币掉出罐外，无法全部收集 |
| 4 | 全针拔完、金币全静止却没收齐 | 死 局 / 金币卡在中途，已无解 |

**升级机制**（`Q2Game._promoteToSlotResult()`）：判负之后、金币冻结之前（`LOSE_SETTLE_TIME = 0.6s` 落定窗口内）物理仍在跑；一旦有任何一枚金币真的越过 `SLOT_FAIL_Y(−158)` 落进槽格，就把已判负的结算**就地升级**为「失败 / 金币已落入槽内」——只改文案、不动状态与计时：

- 面板还没弹出（`RESULT_UI_DELAY = 1.0s`）→ 弹出时直接是新文案；
- 面板已经弹出 → 当场刷新两行文字，不重播淡入。

| 拔 hg-2 时刻 | 首枚入槽耗时 | 是否在 0.6s 落定窗口内 |
|---|---|---|
| 2.0s | 0.23s | ✔ |
| 2.7s | 0.28s | ✔ |
| 3.0s | 0.20s | ✔ |
| 3.5s | 0.20s | ✔ |
| 4.0s | 0.20s | ✔ |
| 4.5s | 0.25s | ✔ |
| 5.0s | 0.40s | ✔ |

7/7 都在 0.20~0.40s 内发生，远早于 0.6s 冻结与 1.0s 弹面板 —— 所以只要预判判了「无解」，玩家实际看到的结算基本都会是「失败 / 金币已落入槽内」（因为物理上确实漏了），「死 局 / 金币最终会落入底部槽位」只会在极少见的"预判无解但落定窗口内还没落进槽"的情况下作为兜底文案出现。

- 代码改动：`Q2Game.ts`（`update()` 金币循环把 `slot` 提前判断并区分「playing」与「已判负」两种状态、新增 `_promoteToSlotResult()`）；`tsc --noEmit` 0 error。
